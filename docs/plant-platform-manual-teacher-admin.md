# 教师与管理员操作手册（植物观察 v1.0）

> 适用版本：全国植物观察与交流平台 1.0（仓库分支 `release/plant-platform-1.0-rc1`）
> 适用对象：试点学校教师（班主任/生物/科学教师）、系统管理员
> 关联文档：`docs/plant-platform-transformation.md`（改造实现说明）、`docs/plant-platform-operations.md`（运维说明）、`docs/plant-platform-manual-student.md`（学生手册）、`docs/plant-platform-v4-production.md`（上线基线）、`docs/plant-platform-pilot.md`（试点运行说明）、`docs/plant-map-data-source-and-compliance.md`（地图数据合规）
> 学生端操作见 `docs/plant-platform-manual-student.md` 与学生 App 帮助；本手册只讲**教师与管理员**在 Web 端的操作，以及两个角色在 **RC1** 中只能通过接口完成的能力（文中明确标注“接口级”）。

## 1. 角色与权限总览

### 1.1 三个角色与植物模块权限矩阵

| 能力点 | 学生 | 教师（tea1） | 管理员（admin） |
|---|---|---|---|
| 采集/编辑/提交植物观察、上传照片、提新物种建议 | ✅ | — | — |
| 审核中心：待审列表、审核详情、通过/驳回 | — | ✅ | ✅（接口可复用） |
| 设为优秀观察 / 取消精选（仅已通过记录） | — | ✅ | ✅（接口可复用） |
| 批量通过 / 批量驳回 | — | ✅ | ✅（接口可复用） |
| 新物种建议处理（通过建档 / 驳回） | — | ✅ | ✅（接口可复用） |
| 观察记录治理：查看记录列表、强制下线 / 重新上架 | — | — | ✅ |
| 植物类别、标准物种库维护（新增/编辑/启停） | — | — | ✅ |
| 图片健康检查、媒体一致性扫描 | — | — | ✅（接口级） |
| 社区互动：评论、1~5 星评分（公开观察详情页） | ✅ | ✅ | ✅ |
| 评论治理：隐藏不当评论、教师点评置顶 | — | ✅ | ✅ |
| 用户/班级/账号管理 | — | — | ✅ |

> 说明：教师端与管理员端的植物审核/建议接口在服务端允许 `TEACHER` 与 `ADMIN` 两个角色调用；Web 菜单按角色分别露出（见 2.1、3.1）。

### 1.2 观察记录状态与“公开”判定

状态流转（后端常量 `PlantStatuses`）：

```
DRAFT（草稿）──提交──▶ SUBMITTED（待审核）──教师通过──▶ APPROVED（已通过，自动公开）
                            │                    └──教师驳回──▶ REJECTED（已驳回，学生可修改后重提）
                            └── 管理员治理 ──▶ OFFLINE（已下线，仅从 OFFLINE 可重新上架）
```

**公开判定规则（全平台一致）**：只有 **status = APPROVED 且 is_public = 1** 的记录才会进入公开端「首页展廊 / 植物观察展廊 / 公开详情 / 中国地图 / 公开搜索」，游客无需登录即可看到。教师“通过审核”即同时完成“发布”动作（系统自动置 `APPROVED` + `is_public=1` 并写入发布时间）。

### 1.3 演示账号与旧域区分

- 演示账号（本地/演示环境种子）：管理员 `admin / admin123`、教师 `tea1 / admin123`、学生 `stu1、stu2 / admin123`（班级“1班”，班级种子 1班/2班/3班 由既有 V6 迁移提供）。
- 本平台是在学院作品展示平台基座上增量建设的。Web 教师端/管理端菜单中除下述植物功能外，其余如「作品评分、评分记录、排行榜、审核管理、评论管理、审核规则、奖品配置、评分批次」等属于**旧“作品”域**保留功能（部分页面入口标注「旧· / 旧版」）。**植物试点阶段请勿混用**：旧域“作品审核/评分”与植物观察审核是两套流程。

## 2. 教师端操作（Web）

### 2.1 登录与入口

1. 浏览器打开平台地址，点击「登录」，输入教师账号（试点中通常为 `tea1` 或管理员为您开通的账号）与密码。
2. 登录后进入教师端布局（侧边栏品牌为“教师评审席”），侧边菜单中**植物观察相关入口**为：
   - **植物观察审核**（`/teacher/reviews`）——学生提交记录的审核中心；
   - **新物种建议**（`/teacher/suggestions`）——学生建议新物种的处理入口。
3. 其余菜单（教师工作台、作品评分、评分记录、排行榜、消息通知）沿用旧评审席布局；“作品评分”等仍属旧域功能，与植物无关。
4. 教师的社区互动（点评、评分）在**公开端的植物观察详情页**完成，见 2.6。

> 入口快捷方式：菜单上方“植物观察审核”与“新物种建议”两个菜单项排在工作台之后，是植物业务的日常主入口。

### 2.2 审核中心：单条审核（植物观察审核）

页面标题「植物观察审核」。页面顶部是一行**实时统计**（数据源 `GET /api/teacher/plant/dashboard`）：

`待审 N · 今日提交 N · 今日通过 N · 今日驳回 N`

统计值随列表加载自动刷新，便于先看整体积压再处理。

**① 筛选待审列表**

- 右上角状态下拉框：**待审核 / 已通过 / 已驳回**（默认“待审核”）。
- 旁边的搜索框为**本地筛选**（按 提交人 / 植物名 / 上报名 过滤当前页），不清除条件时按回车或点击分页即重新从服务端拉取。
- 列表每行显示：封面缩略图（无图显示 🌿 占位）、植物名（优先标准物种中文名，其次学生上报名，都没有则“未命名植物”）、提交人 · 班级 · 省市区、提交时间、照片数、操作按钮。

**② 打开审核详情**

点击行内「**审核详情**」按钮打开“审核植物观察”对话框（宽度 860px），内容包含：

- 全部照片（可点击大图预览，图片加载失败会自动降级不阻塞页面）；
- 记录元信息：提交人、班级、地点（省/市/区县 + 手填地点描述）、**观察时间**；
- 学生填写的观察描述与**动态描述项**（如生活型、花色、器官等字段及其取值，具体字段由管理端/教师配置）；
- **最近审核意见**（若该记录曾被处理过，历史意见会展示，便于再审）；
- 当前状态。

**③ 审核通过**

- 仅当记录处于**待审核**状态时显示「**通过审核**」按钮。点击后弹出意见输入框（选填），提交后：
  - 记录状态置为 **已通过（APPROVED）并公开**，系统提示“已通过审核，记录进入展廊与地图”；
  - 同时写入一条审核留痕（操作人、动作、意见、时间），学生可在本人记录中看到结果与意见。
- 通过时可**绑定标准物种**（推荐操作，保证物种库口径统一）：服务端通过接口支持 `bindSpeciesId`（见第 6 章附录）；绑定后记录自动带上该物种与类别，若学生未填上报中文名则自动回填物种中文名。**RC1 的 Web 审核对话框尚未提供物种选择控件**，该能力目前为接口级；界面版本预计在试点后迭代补齐。
- **质量提示**（见 2.4）仅供参考，**不拦截**通过操作。

**④ 审核驳回**

- 点击「**驳回（需填写意见）**」；**驳回意见为必填**，未填时系统提示“驳回时必须填写意见”并阻止提交。
- 驳回后记录状态置为 **已驳回（REJECTED）**，学生可进入“我的植物观察”修改后**重新提交**；系统提示“已驳回，学生可修改后重提”。
- 意见请写清修改点（如“请补充清晰的叶背面照片”“请选择标准物种或标记待鉴定”“观察时间与照片不一致”），便于学生一次改到位。

**⑤ 设为优秀观察 / 取消精选**

- 只对**已通过**的记录生效（待审记录不显示该按钮）。
- 列表行内：对已通过记录点击「**设为优秀**」→ 再次点击变回「**取消精选**」；
- 审核详情对话框中：对已通过记录显示「**推荐/取消优秀观察**」按钮，可切换精选状态。
- 精选后的记录会进入公开首页“优秀观察”区块与展廊“精选优先”排序，是教师运营“展示标杆”的主要手段。系统记录精选时间与操作人。

**⑥ 审核注意事项**

- 审核意见 ≤ 500 字（接口校验）。
- 逐条审核时请先看“最近审核意见/历史”，避免重复驳回同一问题。
- 若同一学生反复提交相同内容，可参考 2.4 的“疑似重复提交”提示审慎判断后与对方沟通。

### 2.3 审核中心：批量审核

当积累多条同类待审记录（如同一任务批量提交、问题一致）时使用：

1. 在“待审核”列表勾选多条记录（表格首列复选框），页面出现批量操作条：**已选 N 条** + 「**批量通过**」「**批量驳回**」。
2. **批量通过**：点击后无需意见，直接对所选记录执行通过并公开。
3. **批量驳回**：点击后弹出对话框**必须填写统一驳回意见**（“请填写驳回意见”），该意见会应用到所选全部记录；不填意见会取消本次批量驳回。
4. 完成后提示“批量通过完成/批量驳回完成”，列表刷新。

> 接口语义：`POST /api/teacher/plant/reviews/batch`，参数 `observationIds[] + action(APPROVED|REJECTED) + comment`，服务端逐条校验“必须在待审核状态”，不会误处理已驳回/已下线记录。

### 2.4 审核参考：数据质量提示（只提示、不拦截）

服务端在审核详情数据中会为**非已通过**记录自动计算**质量提示**（`qualityWarnings`，V4 §70），供教师参考；系统**不会**据此自动拦截或拒绝。

| 提示文案 | 含义 | 建议处理 |
|---|---|---|
| 缺少照片 | 记录无任何照片 | 要求学生补充至少 1 张清晰照片（提交校验其实要求 ≥1 张，若仍出现说明存在异常通道） |
| 缺少省份 | 未选择省（省市区为 GB/T 2260 行政区代码，学生主动选择） | 要求学生补齐地点 |
| 未选择物种也未标记待鉴定 | 学生既没绑标准物种，也没把鉴定状态标为“待鉴定” | 教师在通过时绑定标准物种，或驳回要求学生补选/标注 |
| 观察时间晚于当前时间 | 填写的观察时间在未来 | 请学生核对观察时间 |
| 该学生该物种在相同省份可能重复提交 | 同学生、同物种、同省已有通过的类似记录 | 核实是否重复内容，避免展廊灌水 |

> RC1 中该提示随审核/详情接口返回；学生端（App）在本人记录详情页也用 ⚠ 形式展示同类提示供其自查。Web 教师审核对话框的提示展示位在后续迭代完善——界面缺失不等于规则缺失，如遇可疑记录建议先在列表/详情里核对照片与地点字段。

### 2.5 新物种建议处理（新物种建议）

页面标题「新物种建议（待处理 N）」。学生找不到匹配标准物种时，可提交“建议内容（中文名/学名/说明）”，建议进入本页待处理队列。

1. 列表展示：建议中文名（加粗）、学名（斜体灰字）、说明、学生标识、状态、提交时间。
2. 「**通过（自动建档）**」：点击后弹确认框“确认通过该建议？系统将使用建议名称自动创建标准物种。”确认后：
   - 系统自动创建**标准物种**（启用状态、来源标记为“学生建议-教师确认”），并回填到建议记录（关联物种）；
   - 新物种随后出现在管理端「植物物种库」与公开端物种搜索中（前提：启用状态且类别可用）。
3. 「**驳回**」：弹出输入框**必须填写驳回说明**；驳回后学生可见原因。
4. 若学生建议的植物其实是物种库里已存在的（换名提交），可走接口级能力：在 `decide` 时传 `linkedSpeciesId` 直接绑定既有物种（见第 6 章附录）。

> 操作纪律：只有确认名称/信息基本可靠才“通过建档”；拿不准的优先驳回并说明，或交给管理员在物种库统一维护（建档是给全平台物种库“加数据”，影响所有学生的选择列表）。

### 2.6 教师点评与星级评分（社区互动）

教师对**已通过且公开**的观察记录的互动，发生在**公开端植物观察详情页**（如 `/plant/observations/{id}`），教师账号登录后访问即可操作：

1. **星级评分**：点击详情页「**我要评分**」为记录打 **1~5 星**。评分规则为“一人一记录一条”：同一教师再次评分会**覆盖原评分**（upsert），记录页展示平均分与评分人数。
2. **点评（评论）**：在“评论与点评”区发表评论；教师账号（或管理员）发表的评论自动带「**教师**」标识，用于与普通学生评论区分。
3. **置顶点评**：教师点评可被置顶，置顶后的教师点评会出现在公开首页“最新教师点评”区块，起到示范导览作用。置顶/取消置顶与不当评论的**隐藏**在 RC1 为接口级能力（`/api/community/plant`，见第 6 章附录；教师只能置顶自己的教师点评，管理员可置顶任意评论）。
4. 内容安全：评论先经**敏感词 + AI 内容审核**，未通过会被拦截；同一用户 1 分钟内发表超过 20 条会被限频拒绝。

> 教师点评是试点期内容运营的重要抓手：每个优秀观察配 1~2 条专业点评并置顶，公开首页即形成“教师推荐榜”。

### 2.7 日常审核节奏建议

- 固定每日 1~2 个审核时段，先看统计条“待审数”，避免积压造成学生等待。
- 同质批量（一次任务几十条）用批量通过/驳回；混有需要单独意见的，先单条处理再批量。
- 建议为真正优秀的记录“设为优秀”，并为其中几条写点评（可置顶）。
- 审核意见与学生沟通可复用「消息通知」菜单查看系统通知（如学生重新提交的提醒）。

## 3. 管理员端操作（Web）

### 3.1 登录与入口

1. 使用管理员账号（演示环境 `admin / admin123`）登录，进入管理端布局。
2. 左侧菜单点击「**植物平台**」（路由 `/admin/plant`，页面标题「植物平台管理」）。页面含两个页签：**植物类别**、**植物物种库**。
3. 管理端其余菜单（审核管理、评论管理、审核规则等）均属旧“作品”域；**“评论管理”是旧域作品评论治理页，不是植物评论治理**——植物评论依赖自动内容审核 + 教师/管理员在社区接口的隐藏/置顶治理（见 2.6、第 6 章）。

### 3.2 植物类别维护（页签“植物类别”）

用于维护观察记录与物种的分类树（初始种子 4 个类别，试点学校可按需扩展，如“乔木/灌木/草本/藤本/水生”等维度）。

- 列表字段：名称、编码、说明、排序、启用（是/否）。
- 「**＋ 新增类别**」或行内「**编辑**」打开对话框：
  - **名称、编码必填**（编码建议短英文/拼音，保持稳定，改编码会影响已关联数据的口径）；
  - 说明（选填）、排序（数字，越小越靠前）、启用开关（1 启用 / 0 停用）。
- 保存后列表立即刷新。停用类别后：公开端类别列表、物种选择等不再展示该类别（停用前请确认不影响已公开记录的展示口径）。

### 3.3 植物物种库维护（页签“植物物种库”）

标准物种是学生观察“物种绑定”与展廊聚合的中枢。RC1 种子含 5 个标准物种（银杏、珙桐、牡丹、狗尾草、爬山虎）；试点中大部分新物种来自教师“新物种建议—自动建档”或管理员手工维护。

- 工具栏：搜索框（**中文名/学名**，回车或点「**搜索**」）、类别下拉筛选、「**＋ 新增物种**」。
- 列表字段：中文名、学名、科/属、类别、启用、操作（编辑）。
- 新增/编辑对话框字段：
  - **中文名（必填）**；
  - 学名（示例占位 `Ginkgo biloba`）、科、属；
  - 类别（从已启用类别中选择，可留空）；
  - 别名（逗号分隔，便于搜索命中）、介绍（多行）；
  - **启用**开关。
- 保存提示“已保存”。注意：物种的“来源”字段由系统写（管理员新增=“管理员维护”，教师通过建议建档=“学生建议-教师确认”），无需手工填。
- 启停语义：公开端首页“物种数”统计只统计启用物种；停用物种不影响已公开观察记录的展示（观察记录快照了物种信息），只影响后续搜索/选择。

### 3.4 观察记录治理：查看、强制下线、重新上架

用途：对**已公开内容中的违规/争议记录**进行治理（错误鉴定、敏感内容、隐私泄露、抄袭盗图等）。

**治理语义（重要）**

| 动作 | 结果 |
|---|---|
| **强制下线** | 状态置 `OFFLINE` 且 `is_public=0`，记录**立即从首页展廊、展廊、地图、公开详情、公开搜索移除**；不删除数据库记录，不删除物理图片文件，学生端本人仍可见其状态 |
| **重新上架** | 仅对 `OFFLINE` 记录有效；状态回 `APPROVED`、`is_public=1`、刷新发布时间，记录重新进入公开数据 |

**RC1 操作方式**：观察记录列表与下线/上架在 **RC1 为接口级能力**（Web 的「植物平台」页暂未提供治理页签），管理员用接口执行，示例（Linux/Git Bash）：

```bash
# 1) 获取管理员 token
TOKEN=$(curl -s -X POST http://127.0.0.1:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"admin123","rememberMe":false}' \
  | python -c "import sys,json;print(json.load(sys.stdin)['data']['token'])")

# 2) 治理列表（可按状态/班级/物种筛选，默认按创建时间倒序）
curl -H "Authorization: Bearer $TOKEN" \
  "http://127.0.0.1:8080/api/admin/plant/observations?page=1&size=20&status=APPROVED"

# 3) 强制下线某条记录
curl -X POST -H "Authorization: Bearer $TOKEN" \
  "http://127.0.0.1:8080/api/admin/plant/observations/<observationId>/offline"

# 4) 重新上架
curl -X POST -H "Authorization: Bearer $TOKEN" \
  "http://127.0.0.1:8080/api/admin/plant/observations/<observationId>/online"
```

> 治理流程建议：先通过详情核对事实 → 下线并**联系带班教师/学生**说明原因与整改要求 → 学生整改后由教师审核通过并公开（或由管理员确认后直接重新上架已整改记录）。

### 3.5 图片健康检查与媒体一致性

植物图片持久化在 `./data/plant-media/`（original / thumbnail 双目录），由后端与 Nginx 共享；管理端提供两个**只读检查**接口（只报告，**不自动删除**）：

- `GET /api/admin/plant-media/health` —— 存储根目录、原图/缩略图目录可读写性等健康状态；
- `GET /api/admin/plant-media/consistency` —— 数据库记录与磁盘文件的比对（缺文件/孤儿文件等）。

示例（续用上面的 TOKEN）：

```bash
curl -H "Authorization: Bearer $TOKEN" http://127.0.0.1:8080/api/admin/plant-media/health
curl -H "Authorization: Bearer $TOKEN" http://127.0.0.1:8080/api/admin/plant-media/consistency
```

发现不一致时：**不要手工删除文件**；先备份（`python -X utf8 scripts/backup-plant.py`），再按 `docs/plant-platform-operations.md` 排查（如图片迁移、目录挂载、Nginx 缓存）。建议**每周或每次备份恢复后**跑一次 consistency。

### 3.6 与试点相关的其他管理员职责

- **账号与班级**：管理端「用户管理」创建/维护学生、教师账号与班级归属（试点建班与开号见试点说明文档检查单）。植物记录展示班级时使用提交时的班级快照。
- **数据字典**：班级等字典项在「数据字典」维护（植物试点通常复用既有班级字典 1班/2班/3班，可扩展试点班级）。
- **通知**：审核结果、评论等系统通知经「消息通知」与各端铃铛下发。

## 4. 内容安全与审核红线

### 4.1 红线一：审核通过 = 立即公开

教师点击「通过审核」即完成**公开发布**，该记录会立刻出现在游客可见的首页/展廊/地图/详情页。因此审核请按“发布前最后一道闸门”的标准执行，而不是“先过了再说”。无法确认植物名时，宁可驳回或绑定“待鉴定/上报名”后再公开，也不要放行明显错误的信息。

### 4.2 红线二：哪些内容不能公开（违规示例速查）

**可以公开**（平台设计如此）：观察照片、植物名/学名、观察日期、省/市/区县与手填地点描述（如“操场东侧花坛”）、班级名、经掩码策略处理的姓名、教师点评。

**不能公开，审核/治理时必须拦截或下线**：

- 学生**家庭住址、门牌号、电话、微信号/QQ、社交账号**等可定位/联系到个人的信息（地点栏只允许模糊到公共场所描述）；
- 含他人肖像、可识别个人的合影（尤其未成年人）且**未获授权**；
- 非本人拍摄/盗用的网络图片（与手填地点、观察时间明显矛盾）；
- 广告、谩骂、政治敏感、色情低俗等任何违规文字/图片；
- 重复灌水内容（同一学生同物种同省反复提交近似照片）。

> 平台技术底座已做防护：**不采集学生 GPS/定位**；地点由学生按 GB/T 2260 三级行政区**主动选择**省市区后手填详细地点，Nginx 已禁用 geolocation 头；公开处姓名展示走统一掩码函数（规则见 4.4）。但文本内容仍以教师审核意见 + 管理员治理兜底。

### 4.3 红线三：审核意见与处置规范

- 驳回**必须填意见**；意见具体、可执行（指出问题点与改法）。
- 已通过的记录**不能由教师撤回/改图**（APPROVED 后不经“下线-整改-重审”不改数据）；若教师发现刚通过的记录有问题，请立即联系管理员下线。
- 下线是管理员专属动作；下线不清数据、不删图，学生可看到状态并整改。

### 4.4 平台内置内容安全与防滥用防线（教师/管理员应知）

| 防线 | 规则 | 处置 |
|---|---|---|
| 图片类型/文件 | 仅 JPG/JPEG/PNG/WebP/GIF；扩展名白名单 + 魔数双重校验 | 不符直接拒绝 |
| 图片炸弹防护 | 单文件 ≤10MB；单边 ≤10000 像素；像素总量 ≤5000 万；只解析文件头不解码全图 | 超限拒绝上传 |
| 单次照片数 | 每条观察 ≤10 张（`plant.storage.max-photo-count`），自动生成 320px 缩略图（jpg/png） | 服务端校验 |
| 评论 | ≤1000 字；先过敏感词（DFA）+ AI 内容审核；限频 20 条/分钟/用户 | 未过审或超频直接拒绝 |
| 登录防爆破 | 同一账号连续失败 5 次锁定 10 分钟（Redis 计数） | 提示“10 分钟后再试” |
| 越权 | 学生只能操作本人记录（submitter 取自 JWT）；旧作品审核与学生提交通道隔离 | 越权一律拒绝 |
| 姓名展示 | 统一走脱敏函数（1 字→“*”；2 字→保留首字如“张*”；3 字及以上→保留首尾、中间以 * 代替，如“张三明→张*明”“欧阳娜娜→欧**娜”）；是否对外展示真实姓名由部署配置 `plant.privacy.show-real-name` 控制 | 试点上线前请确认该配置符合学校未成年人信息保护要求 |
| 下线 | 管理员下线仅从公开数据移除（状态 OFFLINE、is_public=0） | 不删 DB、不删图 |

### 4.5 违规处置标准流程（管理员）

1. 发现或被举报 → 打开记录详情核对（照片、地点、描述、审核历史）；
2. 确认违规 → 接口执行**强制下线**；
3. 通知带班教师/学生说明原因与整改要求（可先由教师电话/群内沟通）；
4. 学生整改重提 → 教师审核通过（或管理员确认后重新上架）；
5. 涉及图片存储异常 → 按 3.5 检查并备份后再处理。

## 5. 常见问题（FAQ）

**教师侧**

| 问题 | 解答 |
|---|---|
| 审核列表为空但学生说已提交？ | 确认右上角状态筛选是否为“待审核”；若学生记录还在“草稿”未点提交，不会进入列表。 |
| 点了“通过审核”会立刻对外可见吗？ | 会。通过即公开（APPROVED 且 is_public=1），首页/展廊/地图/详情立即可见。 |
| 驳回时没填意见会怎样？ | 系统拦截并提示“驳回时必须填写意见”。 |
| 如何给一条好记录“置顶点评”？ | 教师评论本身带“教师”标识；置顶在 RC1 为接口级能力（/api/community/plant/comments/{id}/pin，教师仅能置顶自己发的教师点评）。 |
| 批量驳回是否每人都能看到我的意见？ | 批量驳回使用同一意见并写入每条记录的审核留痕，学生均可见该意见。 |
| 学生说“被驳回后没地方改”？ | 学生在“我的植物观察”打开被驳回记录即可编辑并重新提交（REJECTED 支持修改重提）。 |

**管理员侧**

| 问题 | 解答 |
|---|---|
| 在哪里给记录下线？ | RC1 的「植物平台」页未提供治理页签，需用接口（见 3.4）；后续版本将界面化。 |
| 下线后图片会被删除吗？ | 不会。下线只改状态与公开标记，DB 记录与物理文件保留。 |
| 如何判断图片是否完好？ | 调 /health 与 /consistency 检查（只报告不删除），或直接访问图片 URL 抽查。 |
| “植物类别/物种”停用了会怎样？ | 停用的类别/物种不再出现在选择与统计中；已公开记录展示不受影响。 |
| 教师能下线记录吗？ | 不能。下线/重新上架是管理员专属（接口 hasRole('ADMIN')）。 |

### 6.1 教师端 `/api/teacher/plant/**`（TEACHER / ADMIN）
